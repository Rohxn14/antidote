# Design decisions

One entry per decision: what we chose, what we rejected, and why. Newest at the bottom.

| # | Decision | Rejected | Why |
|---|---|---|---|
| D1 | The demo opens with a malicious injection; an honest mistake (outdated page) is the optional second act | Opening with the honest mistake | Poisoning is the sharper, more recognisable threat (OWASP agentic Top 10); the same machinery handles both |
| D2 | Reasons are `Justification` nodes with `PREMISE` and `SUPPORTS` edges: AND inside, OR across | Plain `DERIVED_FROM` edges between beliefs | Plain edges cannot record which premises belong *together*. "A and B together imply C" and "A alone or B alone implies C" look identical with plain edges |
| D3 | Source `trust` (trusted, unverified, quarantined) is stored; support (`valid`) is computed. Sources carry an `origin` for lineage | Numeric trust scores | Two clear rules beat a threshold nobody can explain. `origin` stops two copies of one claim counting as independent |
| D4 | Stakes policy: automatic only if reversible, under $5,000 and surviving the loss of any single trusted origin. Configurable demo values | Hard-coded "safety rules" | The numbers are policy, not truth; `app/config.py` says so |
| D5 | Domain: procurement | Healthcare, finance | Easy to follow, money makes the stakes obvious, all data can be synthetic |
| D6 | Detection is rule-based or a user report; a human confirms the quarantine | An LLM detector | Detection is not the product: repair and the gate are. An LLM detector is itself injectable |
| D7 | Preview on a graph copy before repair, with a revision check. Repair approval is separate from purchase approval | Applying quarantines directly | Humans see the blast radius before committing; approving a memory fix must never approve spending |
| D8 | Permissions as a second root: cut | | Scope; two days |
| D9 | All writes go through `app/memory.py`; full least-fixed-point recompute after every write, in Cypher inside FalkorDB; computed fields are a cache; status can move both ways | Incremental updates; computing support in Python | Full recompute is obviously correct on a small graph. Running it in FalkorDB is what makes the graph do the real work |
| D10 | Action gate with order states, checked against the *current* graph at authorize and execute time | Trusting the state when the order was drafted | Memory can change between drafting and executing; that gap is exactly where poisoned decisions slip through |
| D11 | Benchmark against delete-source-only and full rollback, with four metrics | Claims without numbers | Measured comparison against the two obvious alternatives |
| D12 | Pitch: "graph-native recovery layer"; the honest limitation is stated in the README | Claiming guaranteed decontamination | We can only be as complete as the dependencies the agents recorded |
| D13 | Justifications are append-only: reusing an ID is rejected; to revise a reason, add a new justification | Editable justifications (MERGE + SET) | A justification is a historical record of why something was believed. Append-only also makes "exactly one SUPPORTS per justification" easy to guarantee |
| D14 | One Cypher query per logical write. It starts with `MATCH (m:Meta)` and bumps `m.revision` in the same query | Separate write and revision-bump queries | Atomic: the write and its revision bump happen together or not at all. A graph without the Meta node rejects writes instead of half-writing |
| D15 | A justification is rejected unless *every* cited premise exists (the query compares found vs cited counts) | Silently skipping unknown premise IDs | Skipping a premise makes a justification *easier* to satisfy: a typo would fail open. We fail closed |
| D16 | "All premises valid" is computed by counting (premises vs valid premises) | `all()` over a pattern comprehension | FalkorDB does not allow pattern comprehensions inside `WHERE` (found by probing v4.22) |
| D17 | Computed flags are read with `= true`, so a missing flag means "not valid" | Treating missing as valid | Fail closed: a node the engine has not processed yet is never trusted |
| D18 | The engine is checked against an independent reference (Dowling–Gallier linear-time Horn algorithm) on 25 random cyclic graphs, after random trust changes | Only hand-written cases | Valid beliefs are the least model of a Horn program; a second, unrelated algorithm agreeing on 125 graph states is strong evidence the Cypher is right. The reference lives in `tests/` only |
| D19 | Beliefs and decisions are create-once: re-adding the same ID with different content is rejected inside the query, before any edge is touched | Overwriting on MERGE | Silent overwrites would change what old justifications were about |
| D20 | "2 independent trusted roots" = on a throwaway copy, the order is valid when only trusted sources count, and stays valid after removing any single trusted origin. All trusted origins are tested | Counting distinct origins behind the decision; walking the graph to find "origins behind" | Counting is fooled by a justification that needs A *and* B. Walking back means alternating edge directions (`<-SUPPORTS-` then `-PREMISE->`), which a variable-length pattern can't express. Testing an origin that isn't behind the order simply changes nothing, so testing all is correct and simple |
| D21 | A human purchase approval can accept the stakes policy but never override missing support; approving a repair approves no purchase | "Approve" as an override | The climax of the demo: the manager clicks approve on the poisoned order and the gate still blocks it |
| D22 | A repair changes memory only; it does not touch order states. The gate blocks invalid orders when someone tries to act | Repair proactively cancelling orders | Keeps one place (the gate) responsible for actions, and it is checked at the last possible moment |
| D23 | Execute re-checks everything: an auto-authorized order that lost robustness goes back to `pending_approval`; one that lost support is `blocked` | Trusting the authorization | Same reason as D10: the graph can change between authorize and execute |
| D24 | The preview diff is Cypher on the copy: before quarantining, the copy stores `was_valid` / `was_holding`; afterwards one query lists what flipped | Diffing two downloaded snapshots in Python | Keeps the reasoning in FalkorDB; the scratch properties only ever exist on the copy |
| D25 | Orders already executed that lose support are listed separately as "needs a human" | Pretending repair can undo them | Memory can be repaired; real-world actions cannot. Honest about the limit |
| D26 | Stale preview: rejected and its copy deleted; the UI regenerates | Applying anyway | The preview a human approved must be the change that happens |
| D27 | A justification stores `premise_count` when created and holds only if that many premises are valid | Comparing against the PREMISE edges present now | Deleting a source (instead of quarantining it) removes edges, which would silently turn "S AND R" into "R alone". With the stored count, deletion fails closed. Found while designing the delete-source baseline |
| D28 | Agent output goes through `record_*` functions that check it: quotes must appear verbatim in the source; Buyer premises must be currently valid beliefs; the order amount is computed in code | Trusting structured output | The LLM proposes, the code checks. Structured output guarantees shape, not truth |
| D29 | The Researcher reads the raw page, HTML comments included, and is told to record claims without judging truth | Pre-cleaning pages; asking the LLM to spot lies | Realistic scraping agent; detection and repair are Antidote's job, not the extractor's |
| D30 | Tests and the default demo replay hand-authored fixtures in the exact LLM output format; real runs are recorded to `data/fixtures/live/` and labelled with the model | Calling the LLM during the demo | Deterministic demo and tests, no rate limits; honest labelling of which outputs came from a model |
| D31 | Benchmark ground truth comes from the independent reference (Horn least model) over the graph's structure; delete-only = DETACH DELETE with no propagation; rollback = restore the snapshot taken just before the poisoned ingestion; Antidote's repair time covers apply only (quarantine, recompute, verify, audit), since the preview happens before the human confirms | Grading Antidote with its own engine | An oracle that shares no code with the engine makes "0 residual, 0 collateral" a real measurement, not a tautology |
| D32 | Tracks: 01 (Agents That Act on Connected Data) + 02 (Agent Memory and Coordination). For 01, agents get Antidote's graph operations as MCP tools | 02 + 03 (Claude's suggestion: 03 fits with no extra work) | Rohan's call: the action gate is "acting on connected data"; MCP tools make the graph the agents' toolset |
| D33 | LLM provider: Groq through the OpenAI-compatible endpoint; JSON-schema mode with a JSON-mode fallback | Gemini | Rohan's choice; free tier, fast. The fallback covers models without strict schema support |
